# 我们没内置什么

更新：2026-10-15，UX-02D。这里区分当前实现与产品立场。早期版本将计划中的功能写成“都已实现、默认不装”，与代码不符；本轮明确更正。历史提案保留在 Git 历史中，不作为现有能力承诺。下述四条产品立场保持不变。

## 一、三层结构

| 层 | 含义 | 状态 |
| --- | --- | --- |
| 核心 | 文档、编码、标注 | 始终可用 |
| 能力块 | 每个项目可开关的六项已实现界面能力 | 下表列出真实默认值 |
| 产品边界 | 自动编码、云端账号、实时协作、语义检索 | 下文列出立场与理由 |

## 二、核心

文档保存文本和字符范围；编码保存名称、颜色和树位置；标注把一处范围与稳定编码 ID 关联。同一范围可以有多条标注。关闭能力块不删除这些记录。

## 三、能力块与真实默认值

以 `qualicraft/core.py::DEFAULT_BLOCKS`、`web/app.js::BLOCKS` 为准。**新项目默认开启五项，绘图默认关闭；已有项目沿用保存的设置。** 能力块开关控制界面，不是在线安装器。

| 能力块 | 当前提供 | 新项目默认 |
| --- | --- | --- |
| 主题归组（hierarchy） | 编码树、父子关系、含后代计数与筛选 | 开 |
| 备忘录（memos） | 文档阅读笔记、编码/主题笔记、标注笔记 | 开 |
| AI 建议（ai） | 请求预览、建议队列、逐条采纳或拒绝 | 开；配置服务、确认请求后才发送 |
| 洞察（insights） | 关系图与证据定位、频次、文档 × 编码矩阵 | 开 |
| 审计（audit） | 项目活动记录与导出 | 开 |
| 绘图（plotting） | 频次、编码 × 访谈、共现热力图、主题层级、编码累计；图、计数与脚本导出 | 关 |

绘图沿现有 Python 脚本路径生成，所需依赖见 `requirements.txt`；导出包含 SVG、PDF、300 dpi PNG、CSV 与脚本。没有前端替代渲染、R/Docker 自动安装或 TIFF 导出。本轮不改变绘图路径。

交叉表（按文档属性分组）、编码者信度、REFI-QDA、转写、混合研究气泡图等曾出现在早期提案中，**不是当前已实现的可选块**。现有文档 × 编码矩阵不能当作这些功能已经具备的证据；它们也不因列在旧提案里而自动成为本轮任务。

### 开关与工作步骤

侧栏 Tools → Capability blocks 可调整六项能力，设置保存在当前项目中。网站的 Import / Coding / Analysis / Plotting / Export 是五个工作步骤，与六项能力块不同。

空项目的 Enable figure workflow 预设会为本项目加入 hierarchy、insights、plotting、audit，保留现有其他设置；它既不改变新项目默认值，也不打开模型请求。

阅读笔记可以在编码前、中、后写入或修改。项目未记录足以确定笔记原始撰写时序的字段，方法导出不能仅因有笔记就声称研究者先完成熟悉资料阶段。

## 四、真正不做（很短，且都有方法论理由）

这一层才是「不做」。判断标准是：**它违背本项目的立场，而不只是成本高。**

| 不做 | 理由 |
| :--- | :--- |
| **自动编码**（一键生成全部编码） | **方法论立场**。定性研究的效度来自研究者的解释，不是模型的输出。AI 只提建议，必须人工裁决。这不是能力问题，是立场问题。 |
| **云端账号体系 / SaaS** | 数据不出本机是本项目的立足点。做成云端就变成了另一个产品。 |
| **实时多人协作** | 同上。多人意味着服务器、账号、加密、审计——那是另一个产品。 |
| **语义（向量）检索** | **产品边界**。本工具的检索需求是精确的——"所有提到数据共享的引文"，要的是可枚举、可复核的结果。语义检索改变的是这个产品是什么，不是它做得好不好。附带一点：向量检索的召回理由难以向读者交代，而关键词命中可以直接指出。 |

**注意这一层只有 4 条，而且每条都是「立场」不是「成本」。** 上一版我把「多媒体编码」「通用绘图引擎」「词云」都塞进这里，那是错的——它们只是成本高或场景窄，应该放可选块。

## 六、范围决定（是决定，不是缺陷的默认接受）

这一节与「真正不做」不同：这些功能**没有人从方法论上反对**，只是**当前不在范围内**。
写在这里是为了让它们**被看见**，而不是让下次审核把它们当成遗漏。

| 决定 | 理由 | 如果要做 |
| :--- | :--- | :--- |
| **快照恢复入口只在宽屏提供** | 它做的是**从备份恢复项目**——一个针对研究项目的恢复动作，而项目本身在电脑上。在手机上恢复一个不在手机上的项目，不是使用场景。窗口宽度 ≤800px 时，恢复入口（`.save-state` 按钮及其打开的 Snapshots 对话框）由样式表隐藏。**范围仅此一项**：研究编辑自动快照由服务端写入（`Store._snapshot()`，与客户端宽度无关）；UX-32A 的手动阅读标记即时入库，随下一次研究编辑快照收录，或立即导出 JSON 独立保留；旧格式升级／失效标记 reset 前检查恢复点，在手机上仍然工作。 | 放进 `projects` 菜单，或加一个溢出菜单。需要新的测量与截图。 |
| 手动编码对话框在 390px 可用 | 已实测，证据为 `~/qualicraft-review/e2e/p2-5/dialogs-390.json`（`at: 2026-10-11T22:58:17`，由 `tools/e2e/dialogs.py` 产出）：Import / Create code / Export 三个对话框在 390px 下均为 356px 宽、不溢出、关闭按钮在视口内。同一运行的对照组把一个对话框强推到 500px，同一测量确实报告了溢出。 | —— |

## 五、这份清单怎么用

1. **想加功能时先看这里。** 如果在「可选块」里，做成块就行；如果在「真正不做」里，需要先讨论是否要改立场。
2. **汇报时用它。** 导师问「为什么不做 X」，分三种回答：
   - 在核心？→ 已经有了
   - 在可选块？→ **有，默认没装，需要可以点开**（这是最好的回答）
   - 在真正不做？→ 讲立场
3. **它是活的。** 决定被推翻时**不要偷偷删掉**，改成「曾考虑过，因为 X 放弃，后来因为 Y 重新评估」——那本身就是一份设计记录。
