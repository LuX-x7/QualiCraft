# 我们没做什么

> 借鉴 Pi Agent 的做法。它的发布页不堆功能列表，反而专门列出**刻意不做**的事。
>
> 这份清单是**主动的选择**，不是能力不足。它的作用是：防止范围蔓延；在汇报时能回答「为什么不做 X」；让「轻」成为设计立场。

---

## 一、明确不做

### 多媒体编码

**不做**图片、音频、视频的区域编码。只做文本。

**理由**：ATLAS.ti 和 QualiCoder 在这块积累很深，我们追不上。而且文本访谈是医学、公共卫生、社会科学定性研究的主流形态——**把文本这一件事做到最好，比把四件事做到及格更有价值。**

### 实时多人协作

**不做**云端账号、多人同时编辑、权限管理。

**理由**：本地单机是**特性**，不是缺陷。医院伦理审查和 GDPR 场景下，「数据不出本机」正是我们的立足点。多人协作意味着服务器、账号、加密、审计——那是另一个产品。

> 折中方案（未来可考虑）：单机为主，通过**项目文件夹**共享（配合第 5 节的可读文本存储）。

### 通用绘图引擎

**不做** R/Python 沙箱、不做任意图表、不做脚本注入。

**理由**：PRD 里原本计划了 Docker + R + ggplot2 + ComplexHeatmap 沙箱，那是「微生信」模式。但通用绘图引擎意味着依赖管理、安全隔离、版本兼容——**成本极高，且与「轻量本地部署」直接冲突**（要装 Docker）。

**替代方案**：只做 **3 张图，但做到能直接投稿**：
1. 主题共现热力图
2. 组别 × 主题发散条形图
3. 混合研究气泡图（主题频次 × 问卷得分）

用前端渲染，不引入 R/Docker。

### 自动编码

**不做**「一键生成全部编码」。

**理由**：这是本项目最重要的立场。AI **只提出建议**，必须由研究者逐条采纳才进入正式码表。原因有二：
1. 方法论上——定性研究的效度来自研究者的解释，不是模型的输出
2. 信任上——研究者必须能说清「这条编码为什么存在」

**所以 QualiCraft 的 AI 是「提建议的助手」，不是「自动编码器」。**

### 词云 / 网络图 / 语义检索

**不做**。

**理由**：词云在学术上几乎没有解释力；网络图的信息密度低于共现矩阵；语义检索（向量）**不可解释**——你不知道为什么这条被找到。研究者的检索需求是精确的（「所有关于数据共享的引文」），**关键词检索更合适，而且可解释**。

> 这条借鉴自 Instinct：它的记忆检索用**类 grep 的关键词搜索，而非向量检索**。

### 云端账号体系 / SaaS

**不做**。

**理由**：见「实时多人协作」。

## 二、暂时不做（但可能以后做）

| 项 | 为什么缓 |
| :--- | :--- |
| 音频转写（Faster-Whisper） | 需要 GPU 依赖，与「零依赖」冲突。可做成可选块 |
| PDF 导入 | 版式解析不可靠，容易把偏移量搞错。先做 TXT/DOCX |
| REFI-QDA 导入 | 导出比导入容易得多，先做导出（能让结果导回 ATLAS.ti） |
| 编码者间信度（IRR） | 内容分析必需，但主题分析不需要。等 P2 |
| 项目存储改 Git 文本 | 方向对，但是大手术。先做最小原型验证 |

## 三、我们反而要做好的

| 项 | 为什么 |
| :--- | :--- |
| **引文精确溯源** | 每条建议锚在字符坐标上，引文必须能在原文唯一匹配，否则丢弃。这是反幻觉的硬保证 |
| **人工裁决** | 采纳/拒绝必须由人做，决策进审计轨迹 |
| **方法学叙述导出** | 让「你怎么做的」自动成文，而不是事后回忆两周 |
| **数据不出本机** | 本地存储、本地模型可选、发送前强制预览 |
| **可读的项目格式** | 目标是让码表、编码、审计都是人能直接读和改的文本 |

---

## 四、这份清单怎么用

1. **每次想加功能时先看这里。** 如果在这个清单上，先问：是不是真的需要打破它？
2. **汇报时用它。** 导师问「为什么不做多媒体编码」，直接翻到这里。
3. **它是活的。** 如果某个决定被推翻，**不要偷偷删掉，改成「曾考虑过，因为 X 放弃，后来因为 Y 重新评估」**——那本身就是一份设计记录。
