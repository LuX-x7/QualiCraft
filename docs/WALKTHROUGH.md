# 人机交互走查 · 真实数据上的编码流程

**为什么做这个**：单元测试证明代码能跑，但不能回答"研究者用它做质性分析时顺不顺手"。
这份记录是在**真实运行的工作台**上、用**真实的公开转录**走一遍编码流程得到的，不是设想。

**怎么做的**：启动一个干净实例（`data/walkthrough`），用浏览器自动化在真实 UI 上操作，
每一步记录界面状态与卡点。素材是数据集 B（Bologna 19 份意大利语访谈）的一份真实转录，
6,000 字符。

## 发现 1 · 弹窗按钮未翻译（已修）

**现象**：点开「创建编码」，标题是「创建编码」，按钮却是 `Cancel` / `Save code`。
云端设置弹窗同理（`Clear key` / `Save settings`）。

**根因**：`modal(title, body, footer)` 的 **footer 是普通单引号字符串里包 HTML**：

```js
modal(QT('createCode','Create code'), `…`, '<button data-action="close">Cancel</button>…')
```

而翻译脚本只重写**模板字符串里**的裸文本。单引号里的 HTML 完全没被碰到。
一共 **7 处**弹窗 footer 都是这个形态。

**修复**：footer 改成模板字符串，按钮文案包 `QT()`。

## 发现 2 · 三个「＋」按钮，图标相近（待改）

侧栏同时存在：

| 位置 | 文案 | 作用 |
|:--|:--|:--|
| 项目区 | `+ 新建 / 导入项目` | 换项目 |
| 文档区 | `＋` | 导入访谈 |
| 编码本区 | `＋` | 新建编码 |

**我的自动化脚本第一次就点错了**——它想点「新建项目」，实际点开了「新建编码」。
机器会错，人也会。三个入口图标几乎一样，只有位置不同。

**建议**：给三者不同的图标与 tooltip；「新建项目」与「导入访谈」的措辞拉开距离。

## 发现 3 · 项目弹窗里没有"导入转录"入口（待改）

「研究项目」弹窗只有：现有项目下拉、新建项目名、四个预设项目、恢复 JSON。

**没有"导入转录"**。研究者必须先建项目、关闭弹窗、再到文档区点「＋」。
一个自然的动作被拆成两处，而且第二处没有任何提示指向它。

**建议**：在项目弹窗的"创建项目"旁边加「创建并导入访谈」。

---

## 发现 4 · 导入器没有 UI 入口（**最重要**）

这是上一轮工作的直接后果，也是走查中最值得记的一条。

我为 5 个公开数据集写了导入器（OpenQDA CSV / NVivo CSV / QualCoder `.qda` /
ATLAS.ti XLSX / FAIRqual XLSX），**它们只能通过 Python API 调用**：

```python
from qualicraft import ingest
project = ingest.from_qualcoder_qda("data/datasets/bologna_qda.zip")
```

UI 的「导入访谈」只接受**粘贴文本 / TXT / DOCX**。一个研究者拿到合作者给的
NVivo 导出表，在界面上**无处可放**。

**建议**：导入弹窗增加"从其他工具导入"分支，识别扩展名并路由到对应解析器；
导入后展示解析预览（识别到多少文档/编码/标注），再确认。

## 发现 5–7 · 英文残留（已修）

- 粘贴框 placeholder：`Doctor: How did the conversation feel?`
- 空状态：`No codes yet. Add one to start coding.` / `No suggestions in this view`
- 绘图视图：`Figures` / `Base font size` / `The plotting workbench is not installed`

**根因**：与发现 1 同源——都是单引号字符串包 HTML，共 **8 处**。

**修复过程中的一个坑**（值得记下）：扫描单引号字符串的正则用了 `{3,900}` 作下限，
导致空串 `''` 不匹配，于是 `join('') || '<div…>'` 里的引号**错位配对**，
这一处被整个跳过。下限改成 `{0,900}` 后配对才正确。
**用正则解析 JS 字符串边界是脆的**——空串、转义、模板嵌套都会让它错位。

修复后复核：界面英文残留 **0 处**（品牌名 `QualiCraft` 与用户项目名不计）。

## 走查方法的局限（诚实说明）

1. **自动化选区未成功**。应用的选中逻辑由 `#reader` 内的 `mouseup` 触发，
   但每次浏览器求值都是独立执行上下文，`window.getSelection()` 不跨调用保留，
   所以"选中文字→打标"这一段**没有在自动化下跑通**。需要人工在浏览器里确认。
2. **没有真人受试者**。这份走查是"有经验的观察者按脚本操作"，能发现结构性问题
   （入口缺失、命名冲突、语言不一致），但测不出学习曲线和主观摩擦。
3. **未覆盖的路径**：AI 建议审核、导出下载、移动端布局、键盘可达性。

---

## 下一步建议（按性价比排序）

1. **把导入器接进 UI**（发现 4）——这是当前功能与界面之间最大的落差。
2. **合并/区分三个「＋」入口**（发现 2）——改动小，直接减少误操作。
3. **项目弹窗加"创建并导入"**（发现 3）。
4. 人工补测"选中→打标"与键盘可达性。

## 发现 8 · 绘图视图顶部显示 `undefined`（已修）

**现象**：打开「图表」视图，页面副标题位置显示字面量 `undefined`。

**根因**：视图标题表只有三个键：

```js
const titles = { coding: …, insights: …, audit: … };
```

而项目开启绘图能力块后，`state.view === 'plotting'`，`titles['plotting']` 取不到值。

**修复**：补上 `plotting` 键。**这是个典型的"加了新视图但忘了登记"**——
类型系统在这里帮不上忙，因为 `titles` 是普通对象字面量。

## 发现 9 · 演示区左图偏小（待改）

网页上的五模块演示区（左截图 / 右文字）在 1440px 视口下，左侧截图约 400px 宽，
界面细节不可读。**建议**：放宽左栏比例，或给图片加点击放大。

## 关于演示区

按需求做成了**左边真实截图、右边文字**的形态：

- 图片是**运行中工作台的真实截图**（不是示意图），所以访客看到的就是实际界面。
- 五个步骤自动轮播，**一旦访客手动点选就停止自动播放**——自动轮播和读者抢注意力
  比静态的更糟。
- 文案中英双语，跟随站点语言切换。
- 实现在 `components/ModuleShowcase.tsx` + `lib/kernel/blocks.tsx` 的 `showcase` 区块，
  所以它是 CMS 里可拖拽的一个积木，不是写死的页面。
