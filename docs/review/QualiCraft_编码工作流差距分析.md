# 编码工作流差距分析

**日期：** 2026-09-29
**对照基线：** `研究计划.md`（PRD v2.0）模块 B
**代码基线：** `main` @ `9548c24`（含已合并的编码修复与码表层级）

## 一、你要的流程 vs 现状

你描述的完整流程是：**划选 → 高亮 → 文本上方弹出批注小框 → 输入关键字完成 code → code 汇总成类型 → 类型总结成 2-3 个 theme**，且高亮颜色随 code 颜色变化。

逐条核对结果：

| # | 你要的 | 现状 | 结论 |
| :--- | :--- | :--- | :--- |
| 1 | 划选一段文本 | 可以，工具条正常出现 | ✅ |
| 2 | 高亮那段文本 | 可以，但**永远是同一种黄色** | ⚠️ 颜色不对 |
| 3 | **文本上方**弹出批注小框 | 工具条固定在**阅读区底部**，不跟随选区 | ❌ 位置不符 |
| 4 | **输入关键字**即完成 code | 只能从**下拉框选已有编码**；项目里一个编码都没有时才弹新建窗口 | ❌ 交互不符 |
| 5 | **高亮颜色随 code 颜色变化** | **完全没实现**（实测 8 处高亮全为同一色） | ❌ |
| 6 | 可以选不同颜色 | 编码有颜色选择器，但**正文高亮不使用它** | ⚠️ 半成品 |
| 7 | code 汇总成几个类型 | P0 已支持（编辑弹窗里选父级） | ✅ 但**不能拖拽** |
| 8 | 类型再总结为 2-3 个 theme | 结构上支持（`parent_id` 可多层嵌套） | ✅ |

**一句话结论：编码这个动作本身是通的，但你要的"手感"和视觉反馈有 4 处真实缺口。**

## 二、四个缺口的代码证据

### 缺口 1：正文高亮不按编码上色 ← 最严重

**证据 A：** `highlight()` 函数里完全没有颜色逻辑

```js
function highlight(text, start, annotations) {
  ...
  return active.length
    ? `<mark title="${esc(active.map(x=>codesFor(x)?.name).join(' · '))}">${part}</mark>`
    : part;
}
```

`<mark>` 上没有 style、没有 class、没有 `--code-color`。编码名只出现在 `title` 属性里——**必须鼠标悬停才看得到**。

程序化检索：`highlight()` 函数体内 `code-color` / `.color` 出现 **0 次**。

**证据 B：** CSS 用的是全局固定值

```css
:root{ --mark:#fff0ad; ... }
.passage mark{ background:var(--mark); color:inherit; border-bottom:2px solid #dfbd43; padding:1px 0 }
```

**证据 C：** 浏览器实测 8 处高亮的计算样式

| 属性 | 实测值 |
| :--- | :--- |
| 背景色 | `rgb(255, 240, 173)` —— 8 处**完全相同** |
| 下边框色 | `rgb(223, 189, 67)` —— 8 处**完全相同** |
| 内联样式 | 无 |

**对比：** Margin 胶囊标签**是**按编码上色的（`.pill{border-left:3px solid var(--code-color)}`）。所以现在是"标签有色、正文没色"，视觉上很割裂。

**⚠️ 附带发现（改之前必须先想清楚）：** 当**多个编码重叠同一段文字**时，`highlight()` 会把它们**合并成一个 `<mark>`**。实测样本里有一条 `title` 是 `"Model-driven code generation · Model-driven code generation"`——两个编码落在同一区间，被压成一个标签。

**这意味着：光加颜色不够。** 得先决定重叠怎么显示，可选方案：

1. 叠加半透明底色（两个编码 → 混色）—— 实现简单，但两个以上就糊了
2. 取最深层级（叶子编码）的颜色 —— 简单，但信息有损
3. 下划线 + 底色分层（底色给父级 theme，下划线给叶子 code）—— 信息最全，改动最大

**建议方案 3**，因为它同时解决了"主题"和"编码"的视觉分层，正好对应你要的"code 汇总成类型、类型总结成 theme"。

### 缺口 2：批注框不在文本附近

**证据：** `selectionUpdate()` 把工具条写进 `#selection-slot`

```js
$('#selection-slot').innerHTML=`<div class="selection-bar">
  <span>Selected ${end-start} characters...</span>
  <button class="primary" data-action="annotate">Apply code</button>
  <button data-action="analyze-selection">Analyze selection</button>
</div>`;
```

而 `#selection-slot` 在 DOM 里位于 `#reader` **之后**，所以它是阅读区底部的横条，不是跟随选区的浮动小框。

**要做的事：** 用 `range.getBoundingClientRect()` 拿到选区的屏幕坐标，把批注框绝对定位到选区上方（注意处理贴近顶部时翻到下方）。

### 缺口 3：不能输入关键字建码

**证据：** `showAnnotation()` 只有一个 `<select>`

```js
modal('Code this passage', `
  <blockquote class="big-quote">...</blockquote>
  <label class="field">Select a code<select id="annotation-code">
    ${state.project.codes.map(c=>`<option value="${c.id}">${esc(c.name)}</option>`).join('')}
  </select></label>
  ...`);
```

而且有个前置判断：`if(!state.project.codes.length) { showCode(); return; }` —— **只有当项目里一个编码都没有时**才会跳去新建编码。只要已有编码，你就只能从列表里挑，无法边选边建新码。

**要做的事：** 把批注框做成一个带**自动补全**的输入框——输入关键字时实时过滤已有编码，若没有匹配则提供"创建『xxx』"选项，回车即建码并打标。

**⚠️ 注意这偏离了 PRD 原文。** PRD 模块 B 写的是"支持划选新文本片段并快速打上**已有**标签"。你的新需求是"输入关键字建新码"。这是对计划的**细化/调整**，按你说的规则是允许的——但建议同步更新 PRD 那一句，否则后来人会以为实现错了。

### 缺口 4：码表不能拖拽聚合

**证据：** 程序化检索 `app.js`

| 关键词 | 出现次数 |
| :--- | ---: |
| `dragstart` | 0 |
| `draggable` | 0 |
| `drop` | 0 |

而 PRD 模块 B 明确要求"层级码表树（**支持主题拖拽**与色板指定）"。

**现状：** 只能点编码右侧的 `⋯` 进编辑弹窗，用"Group under"下拉框改父级。功能上有，但操作上重。

**要做的事：** 给码表树加 HTML5 拖拽（拖到另一个编码上 = 成为它的子级，拖到空白 = 回到顶层）。**这个可以放后面**，因为下拉框已经能完成同样的事。

## 三、关于"先搭结构还是先做 P1"

**你的判断是对的，而且这正是 PRD 的思路。** 但有个分类问题要指出：

你列的四个缺口，**不能都算作"以后美化"**：

| 缺口 | 性质 | 该不该现在做 |
| :--- | :--- | :--- |
| 1. 高亮按编码上色 | **结构**（视觉语言的基础） | **现在做** |
| 3. 输入关键字建码 | **结构**（核心交互） | **现在做** |
| 2. 浮动批注框 | **交互**（和 3 是同一个界面） | **和 3 一起做** |
| 4. 拖拽聚合 | 交互（但下拉框已能替代） | 可以放后面 |

**配色方案、间距、圆角、动效**——这些才是"美化"。而"高亮用什么颜色编码信息"是**信息架构**，不是装饰。

### 建议顺序

```
第 1 步（现在）：缺口 1 + 2 + 3 一起做
   └ 它们共用同一个界面区域（选区 → 批注框），拆开做会返工两次
第 2 步：缺口 4（拖拽）
第 3 步：P1（文档属性 + 频次表含 % + 交叉表）
第 4 步：P2（多编码者 + 信度）
```

**为什么 P1 往后放：** P1 是**分析**功能（交叉表、信度）。它的输入是你编好的码。现在编码体验还没顺、高亮还分不清编码，先做分析等于在没夯实的地基上盖楼。

## 五、小结

- **编码是通的**，但你要的"手感"缺 4 块，其中 2 块（高亮上色、关键字建码）是**结构问题**，建议现在就做
- **高亮不按编码上色**是最扎眼的缺口，且改之前要先决定**重叠编码怎么显示**
- **先搭结构后美化**的思路正确，但"高亮配色"属于结构，不属于美化
- **P1 建议往后放**，等编码体验顺了再做分析
- 我会在每步操作前先读研究计划；建议把计划纳入仓库管理
