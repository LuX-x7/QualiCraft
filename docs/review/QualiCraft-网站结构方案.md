## 二、标志动画（已实现，`189d141`）

**原来的问题**：逐格淡入，但延迟按数组顺序（逐行从左到右），看起来像打字机，不像"拼出来"。

**现在**：每个方块**从上方落下来并落位**，带一点回弹；延迟按**列**排序，每列**自下而上**，所以是先砌好一列再砌下一列。

实测时间线：

| 时刻 | 画面 |
|:--|:--|
| 0.4s | 2 个方块（1 个正在下落，1 个已落位） |
| 1.4s | Q 已完成，T 的最后一根横梁还在空中 |
| 2.1s | 全部 14 格到位 |

落体距离由格子尺寸推算（`--drop`），所以页头 4px 的标记和英雄区 22px 的标记用同一套缓动都成立。
`prefers-reduced-motion` 下不动。

## 三、第 3 块：五个演示的文案结构（**主要工作量在这里**）

你的要求是：**站在小白角度，看完这 5 段就知道怎么做**。

现在的右侧文案是"这个模块能干什么"，例如：

> Bring the material in — Transcripts, someone else's coding table, QualCoder projects. Five public dataset formats are built in, and the parse result is shown for confirmation before anything is stored.

这是**介绍**，不是**操作说明**。建议每一段改成同一个四行结构：

```
① 这一步解决什么        一句话
② 怎么操作              编号 3–5 步，每步一个动作
③ 做完你会看到什么      界面上出现什么
④ 容易卡住的地方        一句话（可选）
```

以"导入"为例：

> **① 这一步解决什么** — 把手里的访谈稿变成可以逐段阅读、逐段编码的文本。
> **② 怎么操作** — ① 点右上角 Import interview；② 选 TXT 或 DOCX，或直接粘贴；③ 检查解析结果——原始换行决定分段，`Doctor:` / `Patient:` 这类标签会被识别为说话人；④ 确认后导入。
> **③ 做完你会看到什么** — 左侧文档列表多一条，右侧正文按段编号，每段左边有一个行号。
> **④ 容易卡住的地方** — DOCX 只取段落和表格文字，批注、页眉、版式不会保留。

五段的②要能连起来读：导入 → 选中文字打标 → 看关系网 → 出图 → 导出。
**看完五段，等于走完一遍完整流程**——这是这个区块唯一的目标。

> 演示动图（`m1–m5.gif`）已经是真实操作录屏，不用重做；要重做的只有右侧文字。

## 四、第 4 块：两种方法的结构化介绍

建议两栏并置，用**同一套骨架**讲，方便对照：

| | Thematic Analysis | Content Analysis |
|:--|:--|:--|
| 一句话 | 从材料里**长出**主题 | 用**既定类目**去数 |
| 典型问题 | "受访者怎么理解这件事？" | "提到 X 的人有多少？" |
| 编码怎么来 | 开放编码 → 归纳成主题 | 先定类目表 → 归入 |
| 迭代 | 反复回读、改编码本 | 类目稳定后较少变动 |
| 产出 | 主题 + 引文 | 频次 + 交叉表 |
| 工具里对应 | 编码本树 + 关系网 | 频率图 + 文档×编码矩阵 |

**关键一句要写清**：两者不是对错，是**研究问题决定的**。同一个数据集，问"为什么"用 TA，问"有多少"用 CA。

QualiCraft 对两种都支持，区别在**你有没有预先建类目**——这句话能立刻把工具能力和方法选择连起来。

原"六阶段"区块（Familiarisation → Open coding → Searching for themes → Reviewing themes → Defining and naming → Writing up）**放在 TA 这一栏下面**作为展开。

## 五、第 6 块：数据来源（横向滚动）

现在是两张卡片（Tian 2021、TU Delft）。改成横向滚动后建议每张卡片给：

- 名称 + 年份
- 一句话说明**适合练什么**（"没有预设编码，适合练开放编码"）
- 规模标签（几份访谈 / 多少字）
- 许可
- 一个"载入示例"按钮

横向滚动的可用性注意：**必须给可见的滚动提示**（右侧渐隐 + 箭头），否则桌面用户不会发现还有内容。键盘方向键和触控板横滑都要能用。
