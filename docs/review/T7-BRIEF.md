硬性约束（任何一条违反即停止并报告）：

- 不修改工作台（qualicraft/、web/）的行为。工作台图表的渲染路径不变。

## 1. 设计系统（先做，其余都依赖它）

- 色彩：纸面底色（近白、略暖）、正文近黑、次要文字灰、强调色限两种（灰蓝、赭红）。禁止渐变和霓虹色。
- 字体：衬线体用于标题和正文，等宽字体用于编号、元数据、图注。字体自托管，子集化，附许可证文件。
- 间距：8px 基准。正文行宽不超过 68 字符。
- 编号：章节 01–06，图 FIG.nn，表 TABLE.nn，全站统一格式。
- 图注格式：编号 + 标题 + 单位句 + 数据来源。单位句从工作台的 CREDIT 常量读取，不得在网站上另写。
- 保留我们自己的标志：像素方块。不得复制参考页面的点阵动效。

## 2. 首页（六区块，顺序固定）

1. 导航：Method / Workspace / Docs / Data / About / Feedback。删除所有指向私有仓库的链接。
2. 首屏：像素方块逐块拼出 QT 标志（1.2–1.5 秒，完成后保持），一句价值主张，两个按钮。
   - 主按钮"Download and run locally"：在总监确认 Windows 门禁通过之前，保持 disabled，并显示"Windows check in progress"。
   - 次按钮"Open the read-only demo"：旁注"first load about 30 seconds"。
3. 五模块区（见第 3 节）。
4. 两种方法：TA 与 CA 的结构化对照表。列：研究问题、分析单位、编码方式、产出、信度处理、反身性、本工具支持程度。写明：CA 的计数类分析本工具支持更直接；TA 的反身性写作须由研究者完成，备忘录需手动开启。引用：Braun & Clarke（2006, 2019）、Hsieh & Shannon（2005）、Krippendorff（2019, 4th ed.）。引用格式需核对后使用。
5. 不做什么：内容以 docs/NOT_BUILDING.md 为准。四条立场，每条给理由和"如需要可考虑的其他工具"。语义检索一条以删除线标出早先理由，并注明修订。第六节"范围决定"中的快照恢复入口（仅宽屏）需如实写出，范围只限于恢复入口，自动快照在手机上照常工作。
6. 数据与页脚：数据卡片的清单以 qualicraft/datasets.py 为准，不得在网站上另写一份。每张卡片写明许可（名称并链接原文）和 SHA-256 短版。页脚：许可行、"如何引用"、反馈邮箱。缺失的信息留空并列入报告，不得编造。

## 3. 五模块演示区（视频风格）

- 布局：左侧 sticky 的演示区，右侧五个编号步骤（01–05）随滚动切换。移动端改为上下排列。
- 步骤：01 导入、02 编码、03 分析、04 绘图、05 导出。每步文字：一句目标，三条动词开头的操作，一句"你应当看到"。每步不超过 40 个英文单词。
- 演示媒体：每步一段 2–3 秒的 WebM（约 1.5 MB 以内），静态首帧。媒体来自真实界面录屏，走 tools/e2e 的录制流程，并满足总监的验收标准（无汉字、结果可见、无灰罩）。
- 在没有通过验收的录屏之前，用占位框，框内写明"clip pending"。不得放置任何伪造的界面截图。
- 滚动切换用 IntersectionObserver，不得劫持滚动。
- 键盘可逐步前进；prefers-reduced-motion 下显示静态步骤图。

## 4. /report 页（长文风格，示例报告）

- 路由：/report。
- 数据生成：新增 tools/report/build_assets.py，调用工作台导出流程（Bologna 项目），把图的 SVG 与计数 CSV 写入 website/public/report/，并生成 manifest.json，记录 git 提交哈希、生成时间、导出命令、每个文件的 SHA-256。
- 页面：左侧章节目录，IntersectionObserver 监听，当前章节加 aria-current。窄屏时目录折叠到顶部。
- 图表：`<figure>` + `<figcaption>`，每张图提供"以表格查看"切换。
- 文字：只描述图上能看到的数字，不做因果推断，不声称饱和。
- 动效：时长 280–520 ms，ease-out，不用弹跳与视差。图表进入视口时从左到右展开一次。悬停提示淡入 120 ms。reduced-motion 下关闭所有过渡。
- 不得重绘图表。悬停层只读取 CSV。

> ⚠️ 本节最后两条动效要求已被 T7 动效规格取代（图表不做展开动画、悬停不加淡入）。以 T7 规格为准。

# T7 动效规格（按视频逐帧测量，替换第 3 节和第 4 节的动效描述）

参考页面：`https://www.stepfun.com/step-5-preview` 的交互式报告部分。

## 目标

复刻参考页面的动效行为（时长、缓动、滚动联动、节奏），不复刻其视觉资产（字体、配色、点阵画法、图表内容）。视觉资产全部使用我们自己的设计系统。

## 动效参数（已测量）

1. **章节指示器**（左侧目录的当前项标记）
   - 移动方式：ease-out，`cubic-bezier(0.22, 0.61, 0.36, 1)`。
   - 时长：240 ms。
   - 触发：IntersectionObserver 判定当前章节变化时。
   - 不得使用弹跳或回弹。
2. **首屏背景动效**
   - 持续、匀速、低幅度，不加缓动。
   - 不得影响首屏文字的可读性。
   - prefers-reduced-motion 下完全静止。
3. **滚动**
   - 保持浏览器原生滚动，禁止用 JS 劫持或平滑滚动。
   - 章节切换只更新目录高亮，不改变滚动速度。
4. **图表**
   - 不做展开动画。
   - 进入视口时只做一次淡入，时长 240 ms，ease-out。
   - prefers-reduced-motion 下直接显示。
5. **悬停提示**
   - 无测量依据。先不做动画，只做即时显示。待 Codex 完成后由总监决定是否加淡入。

## 版式参数（来自单帧测量，仅供参考，允许 ±3% 误差）

- 左侧目录宽度约占视口 35%，右侧内容列从约 41% 处开始，宽度约 52%。
- 目录项分两级：章节（编号 + 标题）与子项（等宽字体的编号 + 说明）。
- 当前章节有一条细线和一个圆点标记，与标题对齐。

## 验证：用同一套测量方法检验自己的页面

1. 用 Playwright 录屏，帧率 24 fps，分辨率与参考视频相同。
2. 运行 tools/motion/measure.py（新增，逐帧测量章节指示器移动的时长与缓动曲线，以及首屏背景动效的每帧变化量）。
3. 输出对照表：参考值、我们的值、差值。差值超过 ±20 毫秒或 ±10% 的项，需要解释原因。
4. 禁止以"看起来差不多"作为通过依据。
