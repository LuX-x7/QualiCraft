## Implementation and local verification

The full hierarchy uses a tall 300 dpi canvas. Matplotlib's normal tight-save path allocates an uncropped raster for measurement and another raster for the final cropped image. The generated script now measures hierarchy PNG bounds at the exact output DPI using a 1×1 non-painting Agg renderer, then lets the original savefig/PNG encoder draw the final canvas once. Hierarchy SVG and PDF are saved first, before the large PNG allocation. All other figure types retain their save order and ordinary tight-save path. The hierarchy layout, fonts, resolution, bounds, colours, rows, counting and path-containment rules are unchanged; the exported standalone script uses the same fix.

`tests/test_plot_memory.py` adds two meaningful checks: the complete 259-row Bologna script must finish all three formats below 430 MiB (leaving room for the server on a 512 MiB instance), and PNG bytes must match Matplotlib's ordinary tight-save reference at 72/300/600 dpi. The full-corpus guard first failed on the old renderer at **525,352,960 bytes (501.0 MiB)**. The fixed full export measured **319,209,472 bytes (304.4 MiB)** in the independent process. CSV, SVG, PDF and PNG are **byte-identical** to the pre-fix full-corpus baseline at the same DejaVu Sans font and default settings; the PNG remains **3459 × 15341** at 300 dpi. The generated script necessarily changes.

A real website-proxy GET downloads the five-member complete hierarchy bundle: **259 rows, 8 themes**, CRC valid, all four data/image files equal the old baseline, project JSON unchanged and server healthy afterwards. The UI's native keyboard type selection, preview, actual-size viewer, arrow navigation and Escape were exercised in the separate **Bologna · hierarchy export review** copy.
