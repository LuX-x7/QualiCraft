## 1. 建议采用的方案

**按段落手动标记，随项目保存；编码范围只从现有标注派生；阅读位置继续只存在浏览器。** 三者独立，未标记不等于没读、有编码不等于已读／完成，阅读标记不证明理解、分析完成或熟悉资料发生在编码之前。

推荐三种用户状态：`Unmarked` 未标记、`Read` 手动已读、`Revisit` 待回看。首版不做自动标记、批量“读到这里”、阅读时长、完成百分比、跨人身份系统或新增统计。段落单位延续现有 Coding：**每一条非空物理行**，不是空行之间的整段；这是现有 `segments()`／`paragraphs()` 的定义。

标记是**项目的手动工作状态**，不是实名个人阅读证明；共享项目文件也会共享这些状态，UI 不称“My progress”。不写进备忘录、文档 attributes、编码或标注；不依赖 memos／insights 能力块开关。未接受模型建议不进入编码范围。

## 3. 状态与操作规则

| 状态 | 精确含义／触发 | 可操作转换 | 保存方式 |
| --- | --- | --- | --- |
| Unmarked / ○ | 没有有效手动标记；不推断读没读 | 明确点 Mark read 或 Revisit | 当前段落无 mark 记录 |
| Read / ✓ | 用户明确标记这一个完整段落已读 | 改为 Revisit；Clear mark；撤销最近操作 | `status:read` |
| Revisit / ↺ | 用户明确标记这一个段落要回看；不表示从未读过 | Mark read；Clear mark；撤销 | `status:revisit` |
| Needs recheck / ! | 原文身份不匹配导致历史标记失效，是有效性提示，**不是第四种阅读状态** | 阅读照常；旧标记不能套到新文本；确认后 reset | 保留旧 metadata 但不算有效状态 |

滚动、Resume、焦点、搜索、范围跳转、创建／删除编码、AI 建议都不改变阅读状态。离开当前段落不自动写已读；按钮动作也不自动跳下一段。

目标优先采用当前屏幕内被明确聚焦的段落；否则采用吸顶栏下第一条可见段落，延续现有位置语义。选中编码原句不等于选中整个来源范围为已读；跨段引句也只能逐段确认。正文选词时不抢选区。目标有清晰边缘标记，控件获得焦点或按下手势开始时固定所显示的段落身份，不在点击后重新猜目标；焦点段落离开视口后随可见位置更新。

常驻栏显示目标段落，例如 `Mark ¶5 read`。点击时固定项目 ID、文档 ID、文本 SHA、段落两端与 revision；用户切换后，迟到响应不得落到新文档／新项目。保存中继续显示上次确认状态并写 Saving；服务端成功后才变成 Read／Revisit。失败显示 Not saved / Retry，不静默存到 localStorage 冒充成功。相同状态重复提交不产生额外写入／事件／快照。Undo 是新的明确转换；弹条消失后仍可从状态菜单清除，不依赖瞬时按钮。

只读公开演示可查看已有状态／范围，但标记、清除、reset 禁用并解释只读；后端仍按现有鉴权／只读规则拒绝写入。页面打开和旧项目迁移均不能自动标成 Read。

## 4. 界面方案

[静态桌面／手机线框](UX-31-READING-MOCKUP.html)明确标为 **DESIGN PROPOSAL / NOT IMPLEMENTED**；没有脚本或标记功能按钮，仅可用原生锚点比较紧凑／展开两种排版，不是工作台实装截图。假设 P4=Read、P5=Revisit、P6=Unmarked，仅为展示三者独立；源文、坐标、编码数量来自真实 Bologna。

- **常驻区域只保留**：当前文档、当前段落／Resume、当前段落阅读状态、Mark read、Overview，以及现有编码路径。桌面目标约两行；390px 目标三行以内、约 136 CSS px，不把文档元数据和笔记重新铺开。正文继续白底、高对比，不加已读底色。
- **Overview 默认关闭**；展开在常驻栏下方，随正文滚走，不让一个大地图占据固定阅读高度。两条对齐的细轨：Read marks 与 Saved coding；当前位置独立用竖线。两轨均按全文原始字符坐标绘制，不按“每段等宽”混用尺度。
- Read 用低饱和绿和 ✓，Revisit 用赭色／纹理和 ↺，Unmarked 为空白／○；编码范围沿用单一灰蓝色。符号和文字同时存在，颜色不是唯一含义。
- 概览下方提供可操作的段落列表／原生跳转控件，显示状态、触及该段的标注数与来源范围数，完整来源和 Theme › Code 路径可达。细轨不是唯一点击入口，不能让手机用户靠点几像素定位。
- 手机保留相同含义与列表，触摸目标至少 44×44；段落／标注列表按需展开，不把完整长表塞进常驻栏。空项目只有既有导入入口；无标注文档显示“尚无编码范围”，阅读标记仍独立可用。
- 搜索／编码筛选时，概览明确写 Entire document；全局轨道不因过滤偷偷缩短。跳到不可见原文必须点明确的 Show full document 动作才能清除过滤；不把查找／跳转解释为已读，也不覆盖筛选前 Resume 锚点。

键盘：Tab 到明确命名的当前段落动作；Enter／Space 保存。Overview 用 disclosure 和 `aria-expanded`；Escape 关闭并返回触发器焦点。列表可用原生 select＋Go 或分页列表，长文不生成数万 Tab 目标。跳转后目标原句位于吸顶栏下、焦点可见。状态写入结果用短 `role=status` 公告，滚动不重复播报；减少动态效果下不依赖动画。

## 5. 编码范围的显示契约

使用当前文档 `annotations` 中的稳定 annotation ID、code ID、准确 `[start,end)`；来源行与完整代码路径保持可核对。**不新增分析表／统计接口／绘图，也不使用名称作身份。**

1. 只为画连续笔迹，对范围做并集；原始标注不合并、不改写。相邻范围可连续绘制，不能由此宣称共现。
2. 两个代码标同一范围：两条标注、一个来源范围、轨上一个位置；展开仍显示两条实际标注。部分重叠的两个不同范围仍是两个来源范围，笔迹连成一条也不丢 ID。
3. 一条标注跨多个段落时，在每段裁切显示；全篇按 annotation ID 只计一次。每段的“touching this paragraph”数量不可相加当全文总数。来源范围按原始完整 `(document_id,start,end)` 去重，不按裁切端点去重。
4. 选中轨道位置只能作范围预览；实际跳转和精确值来自坐标／列表，不能用像素宽度、合并后的笔迹段数或抽样图像反推数值。
5. 删／合并／重命名编码后，范围从新项目数据重算；阅读状态保持。删掉所有编码不会清除 Read，标 Read 也不会增加 coding 数。原网络、五类图、CSV 与方法单位均不受其影响。

首版不提供阅读或字符“覆盖率”、参与者完成度、饱和度或完成百分比。微小范围可用最小可见笔迹，但不能用视觉宽度作定量声明；列表保留准确端点。

## 6. 推荐存储与版本规则（未来实现）

推荐项目文档内独立 `reading_state`，**项目 JSON 升为 v5**；SQLite 仍存项目 JSON 行，不必新增研究数据表。拒绝用 v4 装新语义来碰运气兼容旧版。当前代码和项目仍是 v4，本轮没有迁移。

结构示意（以下两个标记为假设，不能当作研究者已读事实）：

```json
{
  "version": 1,
  "source_sha256": "f43f005420b55b9fb7c8346d7f9e5c4c0cfb73f46bc295c8ca9c45e561734036",
  "source_length": 18239,
  "segmentation": "nonempty-lines-cp-v1",
  "revision": 2,
  "marks": [
    {
      "start": 872,
      "end": 2681,
      "status": "read"
    },
    {
      "start": 2683,
      "end": 2858,
      "status": "revisit"
    }
  ]
}
```

- 文档 ID 是容器身份；SHA-256 是**原始 UTF-8 文本**身份，长度／端点是 Unicode code points，end exclusive；不去除空格、不转换 CRLF、不按 UTF-16 下标保存。分段版本固定 `nonempty-lines-cp-v1`。名称、笔记、编码树变更不使标记失效；同名新导入文档即使文本相同，也有新 ID 和独立空状态。
- 只保存 Read／Revisit；缺记录即 Unmarked。文本身份一致时，端点必须完整匹配当前非空行，无重复／重叠段落标记，不接受部分选区、浮点／布尔端点、未知状态。`revision` 是文档阅读元数据修订号，不是研究进度。
- 每次明确转换原子提交 SQLite，并写 `reading_mark_set` 工作流审计：文档 ID、source SHA、范围、before／after、request ID、server action time、revision；不复制原句。时间只说明点按钮的时间，不代表实际阅读开始／结束或理解用时。未发生操作不生成审计。
- API 采用 set_status，而非 toggle；请求带 expected_revision、source SHA 和段落两端。跨标签页冲突返回明确 409，刷新最新值后让用户决定，不最后写入覆盖。重复 request ID 不二次执行，返回当前权威状态；旧响应不能回滚新 revision。
- 导航继续使用现有浏览器 localStorage，与项目标记分开。禁用／清除浏览器存储不丢项目标记；后端不可用时位置导航仍可用，但不能伪装已保存阅读标记。公开演示不做设备本地的暗中写入。
- v1–v4 文件在新版本读取时只在内存添加中性空值；不根据已有编码／笔记／审计回填 Read，不在 GET 写数据库。导出文件使用内存中的 v5 格式并明确标注，导出本身不写数据库；首次明确写入才把库中项目保存为 v5，前置从原持久化 v4 JSON 制作并检查一次可恢复快照，失败则不写入。格式说明提示旧应用不能读取 v5。新建项目使用 v5。旧版验证器应拒绝 v5，不能静默丢新字段；本轮不提供降级导出。
- JSON／快照恢复保留有效标记；恢复沿现有规则生成新项目 ID，保留文档身份和范围。界面称 Project marks／Marks restored from file，不声称当前打开者读过。原项目不被覆盖；旧浏览器 Resume 不跨新项目 ID 迁移。
- 若历史 metadata 结构合法、坐标在其声明的旧 source_length 范围内，但绑定了别的 source SHA／长度，保留但标 Needs recheck，不套用到当前正文。确认 Reset 才清除旧标记、绑定新身份；reset 前要检查一份完整恢复点。失败就不 reset。文本身份不符时不强行要求坐标匹配新段落；结构非法／超出声明原长度／重复记录则整笔拒绝，原项目／审计不变；不“尽量导入”后假称完整。

容量门槛：marks 不超过 **50,000 条／项目**，且只允许现有段落锚点。新增阅读元数据必须保持完整 UTF-8 项目 JSON 不超过 **19,000,000 字节**，恢复请求不超过现有 **20,000,000 字节**，审计不超过现有 **100,000 条**；预提交验证，失败返回明确 Not saved，不能截断／覆盖研究记录。这是建议的实现边界，不声称当前项目已有这些阅读限制；既有超限项目不在本轮修复范围。

## 7. 快照、导出和方法规则

| 存储／产物 | 推荐规则 |
| --- | --- |
| SQLite 项目 | 每次确认的手动标记立刻事务保存，跨浏览器通过同一项目读取；不等离页才写 |
| 常规自动快照 | **阅读标记单独保存不触发 30 份研究快照的轮转**；在下一次既有研究编辑快照中一同收入，或现在导出项目 JSON 保留。升级前／reset 前的一次必要恢复点例外；说明必须可见 |

| 恢复普通快照 | 恢复该快照时刻的标记，不从当前项目悄悄混入更新标记；若快照早于阅读变化，这些变化不会凭空恢复 |
| coding CSV／matrix CSV | 原列结构、行、值与含义保持；不加 read 列、不过滤未标记段、不把标记当编码。首版不新增 reading CSV |
| 五类图与图包／报告 | 不变，不引入读标记或新的覆盖统计，不重建报告资产 |
| Methods Markdown | 研究数据、计数、代码本与原笔记原样；若有阅读状态，最多补一段独立 workflow 声明：手动标记不证明熟悉资料、理解或阅读时序；不逐段导出，不写读完率／用时。Integrity 总审计包含新增工作流项时须如实区分，不能误称都为编码活动 |
| 模型请求／AI 建议 | 不包含 reading_state，不依据已读状态自动分析、筛选／发送文本 |
