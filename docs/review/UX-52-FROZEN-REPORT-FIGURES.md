## Available now

Export → Write / edit research report → **Figures** adds up to five existing figures. Choose a standard kind, or first configure the existing Figures view and add its current settings. Captions can be edited and figures reordered / removed. Save generates the images using the unchanged `plotting.bundle`; the saved report freezes the original PNG, SVG, PDF, count CSV and exact standalone script, normalized parameters, numeric result, generation environment and member hashes. No new statistics or drawing algorithm is introduced.

Saved and historical report versions refer to a shared content-addressed asset pool. Caption-only edits reuse the existing asset; history restore does not rerender. After coding changes, writing and captions can continue against the old frozen figures. New / changed figures require deliberate evidence refresh. Refresh preserves old versions. Assets are removed only when no retained version references them. Project JSON and project snapshots retain the pool and references.

Figure generation occurs on a detached project before taking SQLite's writer lock. The short commit rechecks the report revision and live coding fingerprint. Concurrent coding / report changes return 409, preserving writing for resolution; concurrent reading metadata are retained. Generation errors, invalid paths, missing evidence and capacity failures leave report / audit / snapshots unchanged. Authentic render dependency failures retain an explicit failure message. Opening or exporting a restored asset never executes its stored recipe.

HTML embeds the saved PNG at its natural ratio, plus the CSV and recipe downloads. Word embeds the same PNG with editable native captions and the UX-50 heading / quotation styles. Genuinely tall originals continue in labelled contiguous views, with page boundaries chosen near low-ink rows when Pillow is available; square matrices remain complete. The full unmodified originals stay in the ZIP. Word does not recompute or redraw a chart. Word captions are editable; changes made in Word do not update QT. The original coded-source Word remains a native editable tree beside italic full source.

Preview / download offers HTML, editable Word, JSON and a complete ZIP. The ZIP contains the report and five original members per figure, plus parameters, numeric results, environment records and instructions. Standalone report JSON with figures has a `qt-report-package-v1` envelope (`report`, `figure_assets`); figure-free JSON retains the legacy entry format. Project JSON remains the route for restoring the whole workspace. All old four exports, original five figures, website clips / static replacements, CSV tables and downloads are retained. Website and workbench availability text are synchronised; actual Comparative QCA remains explicitly planned.

## Limits

At most five figures per report. Each stored bundle is at most 8 MB compressed / 24 MB unpacked. The existing 19 MB project capacity guard still includes all retained versions and shared assets. Repeatedly changing large figure sets can reach that guard; a rejected save does not silently discard history. This is not an unrestricted capacity claim. Extremely tall Word views are limited to 128 parts; the original SVG is the alternative. The independent-reproduction proof below applies to this environment; package versions and fonts are recorded rather than claiming pixel identity across untested systems.
