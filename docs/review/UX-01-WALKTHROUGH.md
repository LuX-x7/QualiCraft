## 问题清单

优先级针对下一步体验工作：P1 为核心证据路径产生错误结果；P2 为可用性、解释与可信度缺口。当前状态：**UX-01-01 已由 UX-02A 修复并验收；UX-01-02/03 已由 UX-02B 修复并验收；UX-02C 已关闭 UX-01-04/05；UX-01-06…08 仍待实施、待验收**。下面保留问题发现时的复现事实。

### UX-01-01 · P1 · 主题计数包含后代，筛选却只找直接标注

**已关闭：UX-02A（2026-10-15）**。筛选现在包含自身与所有后代的稳定编码 ID。桌面、390px、键盘与控制台已核查，原文、标注、统计和绘图路径未改。修复前失败、修复后测试及截图见[验收记录](UX-02A-THEME-FILTER.md)。

父主题无直接标注、两个子码各一条，侧栏父主题显示 2；点父主题，原文显示 No passages match your filters。点任一子码又能看到原句。S12/S13 与 `browser.json`（paragraphs=0）可复现，数据未丢失。

定位：`web/app.js` 的 `readerHtml()` 使用 `a.code_id===state.codeFilter`；侧栏汇总包含后代。建议默认按主题子树显示，保留“直接/含后代”的单位说明。验收覆盖自身、直接子、多层后代、跨文档和同名 ID；原文/标注不应因筛选改变。

### UX-01-02 · P2 · 图上的片段点没有完整证据与来源定位

**已关闭：UX-02B（2026-10-15）**。直接入口、全文/路径/来源范围、准确定位与返回上下文已验收；下文保留发现时的复现事实。见[验收记录](UX-02B-NETWORK-EVIDENCE.md)。

S15 点编码能展开一个片段点，S16 点 `p:0` 后仍是 Insights，没有全文、来源控制或详情面板；DOM 中 sourceControls=0、quoteVisible=false。当前关系图是结构选择，不是完整证据浏览器。

定位：`qualicraft/analyze.py::network()` 的片段 label 截取前 80 字符，缺少定位所需 document ID、原始范围与 annotation ID；`web/app.js::toggleNetworkNode()` 只改变图的选择/展开。建议从已有标注携带稳定来源标识，提供全文、上下文与返回原文的按钮；不得根据 label 反查或猜范围。下一轮需要明确授权工作台变更。

### UX-01-03 · P2 · 关系图埋在完整频次与矩阵之后

**已关闭：UX-02B（2026-10-15）**。直接入口、全文/路径/来源范围、准确定位与返回上下文已验收；下文保留发现时的复现事实。见[验收记录](UX-02B-NETWORK-EVIDENCE.md)。

S35 的实际完整 Bologna 有 317 条频次、318 列矩阵；关系图顶端为 12,271.97px（当前 857px 高视口）。S36 证明图存在。这解释了“好像没有关系图”的感受。

建议给 Insights 的频次、矩阵、关系图明确入口，保留完整计数的可达性。验收以完整 Bologna 为准：直接进入关系图，返回不丢选择；不是通过删掉记录缩短页面。

### UX-01-04 · P2 · 关系图节点缺少键盘入口和可读名称

**已关闭：UX-02C（2026-10-15）**。图外按钮路径、焦点与单位说明已验收，见[记录](UX-02C-NETWORK-CONTROLS.md)。下面保留发现时事实。

S14/S15/S32/S36：SVG 节点没有 tabindex，片段点无可访问名称；`keyboardNodes=0`。按钮可以用 Enter 打开 Insights，但节点选择与展开无法沿同一键盘路径完成。390px 视口的图内容宽约 247px，还需要图外可用的选择控件。

建议提供有名称的节点或图外树/列表，支持选择、展开、清除和明确焦点；拖拽不能是唯一操作方式。验收包含 Tab、方向键或等价列表导航、Enter、Escape、触摸控件与焦点返回；本轮未验证屏幕阅读器和真实触屏。

### UX-01-05 · P2 · 图例 Passages 实际数的是标注关联

**已关闭：UX-02C（2026-10-15）**。图外按钮路径、焦点与单位说明已验收，见[记录](UX-02C-NETWORK-CONTROLS.md)。下面保留发现时事实。

两条标注在同一文档同一 `[122,193)` 原句上，图例显示 Passages 2；数据核对确认来源范围只有一处，网络生成两个片段节点。现有频次各 1、共现 1、累计不同编码 2 均正确，不能为了让图看起来整洁而改统计定义。

建议把“原句/来源范围”和“原句与编码的关联”讲清楚。证据卡可以显示一处原句的两条关联；若继续每条标注一个点，图例必须如实表达。验收保留所有 ID、原始统计与共现结果，清楚解释数量。

### UX-01-06 · P2 · 默认能力块与教学说明不一致

新项目实际默认 hierarchy、memos、ai、insights、audit 开启，plotting 关闭；S02/S17、`qualicraft/core.py::DEFAULT_BLOCKS` 一致。空项目提示和首页却写“模块默认关闭”，网站方法表还写备忘录须先开启。工作台实际有 6 个能力块，首页 5 个模块实际指 5 个工作步骤。

`docs/NOT_BUILDING.md` 的旧能力表还混合了早期设想，不能据此宣称交叉表、信度、转写、REFI 等已实现；四条产品立场仍保留。建议先校正事实与命名，不擅改默认值，也不趁此实现旧设想。网站文字、帮助与新建项目状态须逐条对上。

### UX-01-07 · P2 · 首页重说明、轻关系解释，部分步骤指向不清

S37 当前可见英文词数 1,315（`document.body.innerText.trim().split(/\s+/).length`，含导航与页脚）。S38 左侧整个工作台缩小后原句难读，右侧主要讲操作步骤；没有一处简洁展示“这一句为什么与这个编码和主题相连”。首页 Analysis 教学又把 co-occurrence heatmap 接在 Insights 后面，实际应进入 Figures。

这是信息组织问题；“词太多”的判断不等于数据或方法应被删掉。建议以一条真实证据关系为主展示、录屏按需查看，方法表/边界/来源渐进展开；将导航 Docs 明确为示例报告入口。见蓝图的逐区块方案和 650–800 词目标。

### UX-01-08 · P2 · 方法记录推断了笔记写作时间

实际导出的 `downloads/methods.md` 把阅读笔记称为编码之前的初步印象。审计中第一条编码为 `2026-10-14T20:09:25.219497+00:00`，笔记更新为 `2026-10-14T20:09:46.002246+00:00`，顺序相反；见 `raw/data-audit.txt` 的 chronology 断言和 S25。

定位：`qualicraft/core.py` 方法记录生成处，无条件写入 `before any coding took place.`。建议只描述项目实际保存的笔记，时间顺序有记录才能断言；不修改已有审计。验收：编码前后写笔记、后来修改笔记、导入项目均不生成无依据的时间叙述。**本轮只记录，未修复。**
