For reflexive thematic analysis, researchers develop and revisit themes through interpretation and writing. QT keeps the saved links and memos; it does not produce that interpretation.

Thematic Analysis

METHOD MAP M1 · v1

Procedure overview, not a completion record. Document your chosen approach and decisions.

  1. 01
    Engage with source

    Read and revisit the full material; record your analytic position.

  2. 02
    Code passages

    Link precise excerpts to researcher-defined codes.

  3. 03
    Develop candidate themes

    Explore patterns of meaning across the coded material.

  4. 04
    Review with full source

    Reconsider candidate themes against excerpts and wider context.

  5. 05
    Define themes

    Clarify the scope, central meaning and names of the themes.

  6. 06
    Write with evidence

    Develop the narrative with quotations and contextual interpretation.

Revisit 04 → 02 · 05 → 03

A general TA orientation, not a declared subtype. Document your chosen approach; reflexive TA is one approach within the family.

Qualitative content analysis also interprets meaning. QT preserves your saved hierarchy, descriptive counts and a document-by-code matrix; it does not calculate inter-coder agreement.

Qualitative Content Analysis

METHOD MAP M1 · v1

Procedure overview, not a completion record. Document your chosen approach and decisions.

  1. 01
    Declare unit and approach

    Document what is analysed and the chosen content analysis approach.

  2. 02
    Select meaning units

    Identify relevant passages while retaining their surrounding context.

  3. 03
    Condense when appropriate

    Shorten meaning units only when this fits the analytic design.

  4. 04
    Code and review categories

    Compare codes and refine categories with explicit analytic decisions.

  5. 05
    Interpret in context

    Consider meaning and abstraction; themes are optional, design-dependent.

  6. 06
    Write with evidence

    Connect categories, interpretation and source quotations in the report.

Revisit 05 → 02

Content analysis is a complete method. It is not a compulsory preliminary stage for TA or Comparative QCA.

Qualitative Comparative Analysis

METHOD MAP M1 · v1

Procedure overview, not a completion record. Document your chosen approach and decisions.

  1. 01
    Define cases and sources

    Declare the case unit and map each case to its source records.

  2. 02
    Define conditions and outcome

    Document each set definition and explicit membership rules.

  3. 03
    Calibrate explicit 0 or 1

    Record researcher judgments, reasons and evidence; missing is not zero.

  4. 04
    Review truth table and thresholds

    Inspect all configurations, mixed outcomes and declared cutoffs.

  5. 05
    Conservative configurations and necessity

    Use eligible observed configurations; no logical remainders.

  6. 06
    Check cases and write

    Review cases and counterexamples before interpreting set relations.

Revisit 06 → 03

Binary crisp-set, conservative, no logical remainders. Set relations do not establish causal proof.

Comparative QCA scope
The binary conservative workflow is available in Insights. Fuzzy and multi-value sets, PRI filtering, intermediate and parsimonious minimisation are outside this implementation. Code counts remain separate; interpretation and calibration remain researcher decisions.

TA and qualitative content analysis share passage coding, hierarchies and memos. Comparative QCA adds explicit case and set calibration. Choose the method that fits the research question; interpretation and reporting remain your work.

05 / WHAT WE LEAVE OUT

Less to navigate.
More room to think.

Keep the mechanics clear. Keep judgement with the researcher.

01Automatic codingThe model proposes; you review each suggestion.WHY +

A one-click codebook would be easy to build and would remove the thing that makes the analysis valid. The model proposes; a person decides, and the decision is recorded.

NVivo, MAXQDA and ATLAS.ti all ship autocoding or AI-assist features.

02Uncontrolled sharingPrivate accounts, separate projects, explicit exports.WHY +

The online workspace saves files on the QT server in your own account. Projects are not public. Share an export only when you choose; local use remains available.

Use the local workspace when a study requires files to remain on your own machine.

03Real-time collaborationShare a portable project file, with its record.WHY +

Sharing live means accounts, conflict resolution and a server holding the data. The project file is portable instead: hand it over and both copies can be compared.

The hosted tools above, which are built for shared projects.

04Semantic (vector) searchReview exact text matches and their source ranges.WHY +

A researcher looking for every quotation about data sharing wants to know why each one came back. Keyword search is explainable; embeddings are not.

That was the first reason, and it is withdrawn: explainability was the wrong frame. The questions this tool answers are enumerable and reviewable — every quotation that mentions data sharing, shown with its offsets — and a recall that cannot be pointed at changes what the product is, not how well it searches.

Keyword hits can be shown; vector recall cannot. The product boundary holds. (Revised 2026-10; the earlier reason is struck through above.)

A local embedding search over the exported JSON, if you want one.

Snapshots: restore entry is wide-screen only

The restore button and its dialog are hidden below 800px, because restoring a project from a backup is something you do at the computer the project lives on. Automatic snapshots keep being written after every change, on a phone too — only the restore entry is desktop-only.
